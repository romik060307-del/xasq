# Rencana Uji OHLI Social v3.6.9

## Persiapan
1. Build dan pasang APK 3.6.9 pada perangkat Android yang menjadi host server.
2. Izinkan notifikasi untuk aplikasi OHLI Social Server dan kunci perangkat admin.
3. Pasang web di belakang HTTPS/tunnel yang tepercaya. Jangan meneruskan port HTTP 8080 langsung ke internet.
4. Siapkan dua nomor uji milik penguji dan akun uji; jangan memakai nomor/akun utama untuk smoke test yang mengubah data.

## Alur OTP manual
1. Pada browser/perangkat B, pilih Daftar dan masukkan nomor WhatsApp B, nama, dan kata sandi.
2. Pastikan APK host menerima notifikasi PENDAFTARAN dengan nomor tujuan dan OTP.
3. Pastikan preview notifikasi di lock screen tidak menampilkan kode; buka perangkat admin untuk melihat detailnya.
4. Admin cocokkan nomor tujuan dan kirim kode tersebut ke nomor B melalui WhatsApp secara manual.
5. B masukkan kode benar. Pastikan akun terbuat dan sesi aktif.
6. Logout pada B, pilih Masuk dengan nomor + kata sandi, lalu ulangi pengiriman OTP manual.
7. Uji kode salah lima kali, kode kedaluwarsa setelah lima menit, pemakaian ulang, dan permintaan ulang sebelum 60 detik. Pastikan server menolak sesuai aturan.
8. Coba POST `/api/login` dan `/api/register` langsung. Keduanya harus ditolak HTTP 410.
9. Uji batas nomor (maksimal 5 request per 24 jam) dan IP (20 request per 10 menit). Batas IP akan kembali kosong setelah proses server restart.

## Uji keamanan
- Pastikan browser hanya mengirim token API normal di header `X-RKM-Token`, bukan query string.
- Pastikan endpoint `/api/me` menolak tanpa token.
- Jalankan tunnel Cloudflare pada perangkat yang sama dengan APK host untuk memvalidasi `CF-Connecting-IP` diterima melalui koneksi loopback. Header Cloudflare dari koneksi langsung tidak boleh dipercaya.
- Pastikan notifikasi hanya terlihat pada perangkat admin yang menjalankan APK host. Jangan meneruskan kode kepada nomor yang tidak cocok.
- Cek log, screenshot, dan file debug agar tidak merekam OTP atau token sesi.

## Uji performa
- Catat median dan p95 waktu respons untuk `/health`, `/api/me`, daftar chat, buka chat, kirim pesan, feed, dan unggah media sebelum/sesudah.
- Uji 2, 5, dan 10 klien secara bertahap; pantau CPU, RAM, ukuran file JSON, waktu tunggu `DATA_LOCK`, dan waktu `saveArray`.
- Ulangi melalui jaringan lokal dan HTTPS/tunnel. Jangan menilai hanya dari kecepatan koneksi internet.
- Jika antrean tetap tinggi, migrasikan storage JSON ke SQLite/DB dengan transaksi dan index; jangan menghapus data lama.

## Kriteria lulus
- OTP benar menghasilkan sesi; OTP salah/kedaluwarsa/terpakai ditolak.
- Pendaftaran baru dan login baru tidak dapat melewati OTP melalui endpoint lama.
- Dua nomor uji dapat mendaftar dan login secara terpisah.
- Smoke test dua akun berjalan dengan bearer token hasil sesi yang telah melewati OTP.
- Uji runtime di perangkat dan benchmark harus dicatat terpisah dari pemeriksaan statis.

**Catatan:** pemeriksaan source statis bukan pengganti build APK, uji dua perangkat, atau benchmark server produksi.
